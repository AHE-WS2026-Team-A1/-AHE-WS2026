## 1. What the IP does

`pwm_axi` is an AXI4-Lite slave peripheral with **three independent 8-bit PWM channels** (red, green, blue).
A processor (MicroBlaze in Lab 3) writes a duty value into a register, and the matching output `pwm_r/g/b`
is high for `duty` out of every 256 clock cycles.

| Property | Value |
|---|---|
| IP VLNV | `xilinx.com:user:pwm_axi:1.0` |
| Bus interface | `S00_AXI` – AXI4-Lite slave, 32-bit data, 4-bit address |
| Clock / reset | `s00_axi_aclk` (100 MHz on Nexys), `s00_axi_aresetn` (active low) |
| Outputs | `pwm_r`, `pwm_g`, `pwm_b` (std_logic) |
| PWM resolution | 8 bit (`G_WIDTH => 8`) |
| PWM period | 256 clock cycles = 2.56 µs at 100 MHz → **≈ 390.6 kHz** |
| Duty cycle | `duty / 256` (0 = always off, 255 = 99.6 %) |

## 2. Register map

| Offset | Register | Bits | Function |
|---|---|---|---|
| 0x00 | CTRL | 0 | 1 = enable all PWM channels |
| 0x04 | DUTY_R | 7:0 | Duty of the red channel |
| 0x08 | DUTY_G | 7:0 | Duty of the green channel |
| 0x0C | DUTY_B | 7:0 | Duty of the blue channel |

All registers are read/write. After reset all registers are 0, so all outputs are off.

Example (C, Lab 3):

```c
Xil_Out32(PWM_BASE + 0x04, 128);  // red 50 %
Xil_Out32(PWM_BASE + 0x00, 1);    // enable
```

## 3. Structure

```
pwm_axi                                  (hdl/pwm_axi.vhd – top level wrapper)
└── pwm_axi_slave_lite_v1_0_S00_AXI_inst (hdl/pwm_axi_slave_lite_v1_0_S00_AXI.vhd – AXI4-Lite slave, slv_reg0..3)
    ├── u_pwm_r : pwm_core               (src/pwm_core.vhd)  enable = slv_reg0(0), duty = slv_reg1(7:0)
    ├── u_pwm_g : pwm_core                                    enable = slv_reg0(0), duty = slv_reg2(7:0)
    └── u_pwm_b : pwm_core                                    enable = slv_reg0(0), duty = slv_reg3(7:0)
```

`pwm_core` is a synchronous, generic counter/comparator: an `G_WIDTH`-bit counter runs freely and
`pwm_out` is high while `cnt < duty`. The output is registered (no glitches), reset is synchronous and
active-low, matching the AXI reset. The AXI handshake code generated by the wizard was not modified;
only the user-port and user-logic sections were edited.

## 4. Verification (simulation)

Self-checking testbench `tb_pwm` (XSim, behavioral) with `G_WIDTH = 4` (period = 16 clocks).
For each duty value the testbench lets one period settle, counts the high cycles over one full
period and `assert`s that the count equals the duty.

| Duty | Expected high cycles | Measured | Result |
|---|---|---|---|
| 0 | 0 / 16 | 0 / 16 | OK |
| 4 | 4 / 16 | 4 / 16 | OK |
| 8 | 8 / 16 | 8 / 16 | OK |
| 15 | 15 / 16 | 15 / 16 | OK |

Console: **`TEST PASSED`** at 1295 ns. Waveform: see `sim_pwm.png` (`cnt` counting 0–15, `pwm_out` widening with `duty`).

## 5. Implementation results

Out-of-context synthesis + place & route of `pwm_axi` on xc7a100tcsg324-1 with a 100 MHz clock
constraint on `s00_axi_aclk` (`create_clock -period 10.000`). Full reports: `pwm_axi_utilization.txt`,
`pwm_axi_timing.txt`.

**Utilization**

| Resource | Used | Available | Util % |
|---|---|---|---|
| Slice LUTs | 86 | 63 400 | 0.14 |
| Slice registers (FF) | 153 | 126 800 | 0.12 |
| Slices | 42 | 15 850 | 0.26 |
| CARRY4 | 3 | – | – |
| Block RAM / DSP | 0 / 0 | 135 / 240 | 0 |

The register count is dominated by the four 32-bit AXI registers (128 FF). Vivado recognised that the
three PWM counters are identical (same clock, reset and increment) and merged them into one shared
8-bit counter; the three `pwm_out` flip-flops and the AXI handshake state machine make up the rest.

**Timing at 100 MHz**

| Metric | Value |
|---|---|
| WNS (setup) | **+6.454 ns** |
| WHS (hold) | +0.181 ns |
| WPWS (pulse width) | +4.500 ns |
| Failing endpoints | 0 |

*All user specified timing constraints are met.* The critical path is counter → 8-bit compare
(CARRY4) → `pwm_out` register (3 logic levels, 3.49 ns data path). With 6.45 ns of slack on a
10 ns period, the IP would run at roughly 280 MHz, so 100 MHz has a large margin.
(The `no_input_delay` / `no_output_delay` notes in the report are expected for an out-of-context run:
the IP has no pins of its own until it is placed in a block design.)

## 6. Part 1 (LED project)

`top.vhd` connects `sw(15:0)` directly to `led(15:0)`; `top.xdc` maps the pins from the Digilent Nexys
A7-100T master XDC (sw[8], sw[9] are LVCMOS18). The bitstream was generated successfully:
0 LUTs, 0 FF, 32 bonded IOBs (16 IBUF + 16 OBUF); no timing paths, as the design has no clock.
